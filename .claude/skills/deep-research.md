# Deep Research Skill

When researching any topic for this knowledge base, you MUST follow this rigorous methodology. Superficial or single-source research is unacceptable. The goal is exhaustive coverage before any documentation work begins.

## Core Principle

**Never start writing documentation until you have achieved information saturation.** You should feel you've encountered the topic from virtually every meaningful angle. If you're uncertain whether you've found enough, you haven't.

## Phase 1: Query Generation & Multi-Vector Search

Before conducting searches, systematically generate query variations:

### 1. Rephrasing & Reframing
- Take the core topic and express it in **at least 5-7 different phrasings**
- Use different terminology: technical terms, layman terms, jargon, synonyms
- Example: "machine learning" → "ML", "predictive modeling", "AI training", "statistical learning", "neural networks"

### 2. Perspective Variations
Search from multiple stakeholder/audience perspectives:
- **Practitioner**: How-to, implementation, tutorials
- **Academic**: Theory, research papers, scholarly analysis
- **Critic**: Limitations, failures, controversies, skepticism
- **Historian**: Origins, evolution, timeline
- **Comparativist**: Alternatives, comparisons, vs. other approaches
- **Future-looking**: Trends, predictions, emerging developments

### 3. Scope Variations
- Broader context (parent domain)
- Narrower focus (specific subtopics)
- Adjacent/related topics that provide context
- Edge cases and uncommon applications

### 4. Source Diversity Requirements
Aim for **minimum 15-25 unique, high-quality sources** including:
- Official documentation and primary sources
- Academic papers and peer-reviewed content
- Industry blogs and practitioner experiences
- Wikipedia (starting point only—verify and trace to primary sources)
- Technical tutorials from multiple authors
- Criticism and counter-narratives
- Recent news (last 12-24 months) for relevance
- Historical sources for context

## Phase 2: Search Execution

Execute searches systematically:
1. Run initial queries with your primary phrasing
2. Identify gaps—what perspectives or subtopics are missing?
3. Run follow-up queries targeting those gaps
4. Chase citations—when a source references another, investigate it
5. Look for "best of" lists, comparisons, and curated resources that aggregate multiple viewpoints
6. Search for common misconceptions to address
7. Search for "X explained" or "introduction to X" from multiple authors

## Phase 3: Synthesis Checkpoint

Before proceeding to documentation:
- [ ] Have you found at least 3 sources that disagree or offer contrasting views?
- [ ] Have you found both historical context and current state?
- [ ] Have you covered beginner, intermediate, and advanced perspectives?
- [ ] Have you identified the main subtopics that deserve their own detailed treatment?
- [ ] Could you explain this topic to multiple audiences (expert, general, skeptic)?

If any checkpoint fails, conduct additional targeted searches.

## Phase 4: Escalation to Perplexity (Optional but Recommended)

If after exhaustive web searching you still lack:
- Nuanced expert perspectives
- Recent developments (past 6-12 months)
- Synthesis across conflicting viewpoints
- Depth on a specific subtopic

**Then invoke the Perplexity MCP skill** to run a Sonar deep research query. Add Perplexity's findings to your research context before documenting.

## Anti-Patterns to Avoid

- **Single-source reliance**: Never document based on 1-3 sources
- **Echo chamber**: If all sources say the same thing, you haven't searched enough
- **Recency bias**: Include historical context, not just latest trends
- **Authority bias**: Include criticism and alternative viewpoints
- **Premature writing**: Documenting before research saturation wastes effort and produces shallow content

## Output

After completing deep research, you should have:
- A mental model (or notes) covering the topic comprehensively
- Source URLs and citations ready for documentation
- Clear identification of complex subtopics requiring separate files
- Confidence that you could defend your summary against a domain expert's critique
